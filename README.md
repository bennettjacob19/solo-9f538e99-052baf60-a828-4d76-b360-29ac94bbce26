# 检查点重分片网页（训练机换卡）

训练机换卡后，检查点要交给不同数量的 rank。本应用用 **Flask + NumPy** 实现重分片：
旧卷上的检查点按 rank 存放（参数 `param`、同段的 Adam 一阶 `adam_m` / 二阶 `adam_v`
状态和训练步 `step`），重分片时把各 rank 的数组按 rank 顺序拼成全局数组，
**三个数组按同一套全局下标连续等分，余数依次分给低 rank，每片都带训练步**，
按新 rank 数写到新卷并提供 NumPy 文件下载。

## 运行

### Docker Compose（推荐）

```bash
docker compose up --build
# 打开 http://localhost:8000
```

数据持久化在命名卷 `reshard-data`（容器内 `/data`）。

### 本地运行

```bash
pip install -r app/requirements.txt
python3 app/server.py          # 数据目录默认 ./data，可用 DATA_DIR 覆盖
```

## 网页操作

1. **旧卷状态**：内置三块样例检查点（正常 3 rank / 训练步不一致 / 缺片）。
   可**模拟卸载**、**挂回同一卷**、**挂载不同卷**（演示卷 ID 不符不恢复可读性）。
2. **重分片**：选检查点，填**新 rank 数**和**新卷容量（字节）**，勾选
   **续训时能否挂旧卷**（勾选则发布结果依赖旧卷）；另有"模拟写失败"开关用于演示。
3. **新卷与当前发布**：显示容量、当前占用（发布 + 暂存）、**分片文件占用峰值**
   （上一套和本次暂存都计入）、发布记录与可读性，按新 rank 下载 npz。
4. **操作历史**：每次重分片的结果与失败原因。

## 发布与失败语义

- 读源前要求旧卷可读（已挂载且为同一卷）；源校验**缺片**、**训练步不一致**直接失败。
- 逐片写入暂存区，**上一套发布 + 本次暂存一起计入容量**，超限即失败。
- 全套暂存分片在**指定挂载条件下回读校验**（存在性、训练步、长度、与源拼接一致）才发布。
- **缺片、训练步不一致、超额、模拟写失败**时：清理暂存、**保留上次发布结果**、历史记录原因。
- 发布时若声明"续训可挂旧卷"，结果标记为依赖旧卷：**旧卷卸载后标为不可读，
  挂回同一卷（卷 ID 相同）后恢复**；挂不同的卷不恢复。不依赖旧卷的结果不受卸载影响。

## 崩溃恢复（进程在发布中途退出后重启）

发布在回读校验通过后会先原子写两个元数据标记，再做目录替换：

1. 暂存目录内的 `manifest.json` —— 标识这是一套**完整分片套**（含发布 id、rank 数）；
2. 新卷根目录的 `pending_publish.json` —— 标识**全套回读校验已通过、待发布**。

进程重启时 `NewVolume` 构造即执行 `recover()`，按磁盘现场收敛，恢复规则：

- **全套回读校验通过之前中断**：没有待发布标记，丢弃不完整暂存；若旧套已被挪到
  备份目录则还原旧套。页面发布编号与各 rank 下载仍指向上一套，**不会再出现
  "页面列旧套、下载 404"**。
- **回读校验已通过（pending 标记存在）**：新套是完整套，优先发布新套——无论页面
  是否已提示成功，重启后都保留新套；若新套意外损坏而旧备份完整，则回退完整旧套，
  即"可恢复任一完整套"。
- **state.json 已保存（成功提示已可给出）后退出**：published/ 与记录都指向新套，
  恢复只清理遗留，原样保留新套。
- 恢复后保证**页面发布编号、发布记录与每个 rank 的下载文件指向同一套**，
  旧卷挂载/卸载规则与数据卷沿用不变。

恢复的实现约束：

- **只读 `manifest.json` / `pending_publish.json` 等元数据，不读取 NPZ 正文，
  不复制分片**；完整套判断只到"声明的 rank 文件是否齐全"的文件名级检查。
- 目录替换只用 rename 级 `shutil.move` 与 `rmtree`，所有 JSON 走"临时文件 + 原子
  replace"，每一步幂等，可安全重复恢复。
- 遗留的暂存、备份目录、临时文件在恢复时和**下次重分片开始时**统一回收；
  清理期间页面仍可打开、当前套仍可下载。下次容量判断在遗留释放之后进行，
  遗留不会再占用容量。

## 已实现

- 按 rank 存参数 + 同段 Adam 一阶/二阶状态 + 训练步的旧卷样例（含缺片、训练步不一致样例）
- 三个数组同一全局下标连续等分、余数给低 rank、每片带训练步
- 选检查点 + 新 rank 数 + 新卷容量（字节）+ 续训能否挂旧卷
- 模拟卸载 / 挂回同一卷 / 挂载不同卷；依赖旧卷的结果卸载后不可读、挂回同一卷恢复
- 新卷占用与峰值展示（上一套 + 本次暂存计入容量）；按新 rank 下载 npz
- 全套在指定挂载条件下回读可读才发布；四类失败（缺片 / 训练步不一致 / 超额 / 模拟写失败）
  保留上次发布并记录原因
- **发布崩溃恢复**：manifest + pending 双标记，重启按磁盘现场收敛；校验前中断恢复旧套、
  校验通过优先恢复新套、已成功则保留新套，页面编号与各 rank 下载始终同套
- **遗留回收**：恢复与下次重分片开始时清理暂存 / 备份 / 临时文件，清理不影响页面与下载，
  下次容量判断先释放遗留
- Docker Compose 一键启动

## 未完成 / 限制

- 本环境无 Docker 守护进程，**镜像构建与 `docker compose up` 未实际执行**，仅静态校验
- 卷为本地目录模拟，非真实挂载点；挂载状态存于 `mount.json`
- 重分片为全量读入内存，未做流式/mmap，超大检查点需要分块流水线
- 单进程串行（锁保护），无任务队列与并发重分片
- 回读校验靠 np.load + 拼接比对，未做逐片 sha256 校验和；恢复路径只做文件名级完整性检查
